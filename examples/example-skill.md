# review — 程式碼審查

## 描述

針對當前分支的未提交變更或指定的 Pull Request 進行結構化程式碼審查。
檢查安全性、效能、可讀性與架構一致性，並給出具體的改善建議。

## 觸發條件

- 完成功能開發後、提交前的自我審查
- 收到 PR review request 需要給出評論時
- 重構既有程式碼之前，先理解現況

## 參數

- `PR_NUMBER`（選填）：GitHub PR 號碼，例如 `/review 42`。省略時審查當前工作區的未提交變更。

## 指令內容

你是一位資深軟體工程師，正在審查以下程式碼變更。

請依照以下結構輸出審查報告：

### 總體評估
一到兩句話說明這份變更的整體品質與風險等級（低 / 中 / 高）。

### 問題清單
針對每個問題，按嚴重程度排序：

**[嚴重]** 必須修正才能合併的問題
**[建議]** 最佳實踐建議，不修正也可合併
**[微調]** 風格或命名的小改善

每個問題格式：
- 位置：`檔案名:行號`
- 問題描述（一句話）
- 建議修法（給出具體程式碼或方向）

### 安全性檢查
- [ ] 無硬編碼憑證或 secret
- [ ] 輸入驗證充分
- [ ] 無明顯 injection 風險（SQL / XSS / command）

### 摘要
三點條列本次審查的主要發現。

---

審查時請特別注意：
1. 只評論本次變更引入的問題，不要批評既有程式碼
2. 給出可操作的建議，而非模糊的「可以更好」
3. 若邏輯正確且風格一致，明確說明「此部分沒有問題」

## 範例

```
/review
/review 123
```
